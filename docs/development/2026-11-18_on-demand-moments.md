# 按需精确取帧复测

2026-11-18，从本机已安装的 `media-lens-mcp` 启动新的 stdio 会话，用原来的三条公开链接新建任务。五道题与[上一轮同链接对比](2026-11-18_agent-video-comparison.md)相同，原片参照和答案已知。本次验收检查 Agent 实际收到的 JPEG、显示时间、同期转写和原声窗口。未操作浏览器。

M1 验收要求 JPEG 与参照中的目标时间和画面细节都一致。旧入口命中 3/5，新入口命中 5/5。M2 验收要求能分辨识别段跨过的停顿。五个请求均交付可解码的 16 kHz 单声道 WAV，音乐末尾的窗口按片尾截断为 3.001 秒，其余均为 4 秒。这轮没有人工逐字听写，也没有测量歌词识别准确率。

## 复测步骤和边界

1. 分别调用 `media_resolve`、`media_analyze({url, discardOriginal: true})`，以默认上限 30 帧、CPU base 转写处理。轮询 `media_get_task` 直到完成，再读 `media_get_result`。三个任务分别产生 24、30、30 张关键帧，均报告 `retained: false`。
2. 针对每道题，在同一任务先调用 `media_get_frame({taskId, timestamp})`，再调用 `media_get_moment({taskId, timestamp, includeAudio: true})`。读取返回的图片、时间标签和实际音频。具体数字从 JPEG 读取，口播转写保留识别段的起止时间。
3. 完成后重开 MCP 会话，对以上任务再次追问五个时刻。每次均重新通过已有访客服务获取该作品，临时文件在返回后清理。复核测试缓存最终只有三个完成任务，没有 MP4。不同轮次的单次取帧实测约 1.4–30 秒，包括重新获取媒体。耗时取决于上游响应和视频体积。

普通概览仍走关键帧。精确追问在已完成的任务上执行，也能复用保留的媒体文件。公开链接失效且本地没有副本时，上游错误会返回给 Agent。与[本地 BiliNote 实测](2026-11-18_bilinote-local-comparison.md)相比，两者都曾取到 B 站 32 秒的正确截图。本插件允许 Agent 在现有会话中用一次工具调用直接取得实帧、同期转写和可选原声。
