# 从抖音和 B 站链接追问画面与口播

2026-11-18，同一个 Agent 通过三个产品的接口读取同一组公开链接，全程没有操作平台播放器。AgentMediaLens 和 bilibili-douyin-notes 均交付了可查看的真实图片和转写。BibiGPT 的请求在鉴权阶段结束。

## 样本和判分

| 公开原片 | 预先指定的追问时刻 | 核对内容 |
|---|---|---|
| [抖音《譬如我》歌词视频](https://www.douyin.com/video/7705364444327233914)，28 秒 | 00:04、00:27 | 读出画面上的字，检查能否从该时刻的转写得到同样的词 |
| [B 站 Mika 技术讲解](https://www.bilibili.com/video/BV1Q34P6vEzR/)，7 分 12 秒 | 00:32、03:36 | 读出屏幕细节和同期口播，尤其是只能从画面得到的数字 |
| [抖音后台管理系统演示](https://www.douyin.com/video/7422312100527148322)，9 分 24 秒 | 00:43 | 补测抖音中文讲解，核对当前界面、字幕与语音活动 |

前两条与项目早期演示用的是相同作品，00:27 和 03:36 已知。五个画面问题均在本轮读取相应结果前锁定。用 PyAV 单独解码源流，取显示时间覆盖指定秒的原片帧。五帧的显示时间恰好都等于目标时间。对照产品交给 Agent 的图片，核对界面、屏幕文字与实际取帧时间。只算指定时刻和可见内容都匹配的图片。有原始图片才能回答视觉题，仅有标题、OCR 或转写不计分。

口播以画面自带字幕作文字参照。音乐视频只核对显示的歌词。教程的 41–46 秒另用离线语音活动检测复核。这些检查没有人工逐字听写，不计算语音准确率。两款本地工具分别使用各自默认的 CPU 模型，结果适用于这里记录的配置。

## 五个画面追问

| 追问 | 原片显示 | AgentMediaLens 0.5.0 返回给 Agent 的 JPEG | bilibili-douyin-notes 自带截图流程 |
|---|---|---|---|
| 抖音歌词 00:04 | 深蓝色方块上写「譬如我」 | `f003`，4 秒，命中 | 指定时刻和候选网格都给了 12 秒，已切到街景大字 |
| 抖音歌词 00:27 | 红底蓝字「小小的花朵」，两旁是白色「开」「出」 | `f023`，27 秒，命中 | 指定时刻与候选区间均未通过转写时间校验，无图 |
| B 站 00:32 | Mika 开源四天，星数 **4,898**，底部字幕「快五千顆星」 | `f002`，39 秒，已经是账号表格。转写能答「快五千颗星」，没有精确数字 | 两种入口都给了 40 秒的账号表格 |
| B 站 03:36 | 手机中央有黄色锁，上方「开发者身份」，底部「配对只要一次」 | `f016`，216 秒，命中。215.04–216.56 秒的转写也给出同一句 | 指定时刻被拒。候选网格给了 220 秒，锁旁多了一把钥匙，字幕已变 |
| 抖音教程 00:43 | 「安全」页面，有三个密码框。底部说明何时需要改密码 | `f004`，51 秒，已经是「基础信息」页面 | 指定时刻被拒。候选为 3、25、56、63 秒，最近的 56 秒是「完成」页面 |

按上述口径，**通过产品自带的单帧或截图入口，AgentMediaLens 命中 3/5，notes 命中 0/5**。这五题专门检查某一秒的可见内容。notes 确实能生成真实的讲解插图。在它取得的同三条媒体上，再由 Agent 显式调用 FFmpeg 按目标秒取一帧，**5/5 都读到了原片对应的内容**，也无需开浏览器。这个补测使用 notes 自己取得的媒体，没有把评测参考图交给它。

## 口播实际能答到什么程度

| 作品 | AgentMediaLens | bilibili-douyin-notes |
|---|---|---|
| 抖音歌词 | 24 帧、4 段转写。「譬如我」在 3.16–6.44 秒被识别成「披入我」。9.68–28 秒整段给出「这笑容去划头」。两个画面都能读字，逐句歌词需要复核 | 全片仅有一条 `[00:00]`。开头识别出了「譬如我」，未给出「小小的花朵」，无法按转写定位结尾 |
| B 站讲解 | 30 帧、294 段转写。30.72–32.32 秒「快五千顆星」和 215.04–216.56 秒「配對只要一次」均与同期画面字幕相符 | 两句话均可搜到。前一句在 `[00:29]` 开头、下一段 00:56，后一句在 `[03:20]` 开头、下一段 03:49。能说明讲了什么，单靠段首不能把句子定位到具体秒 |
| 抖音教程 | 30 帧、32 段转写。39.50–49.71 秒给出「首次等路用户需要歪扇个人新系」，未标低置信。41–46 秒窗口未检出语音。后面 46.50–49.44 秒检出语音，48 秒画面字幕为「首次登录用户需要完善个人信息」 | 开头至 00:54 只有一个段首，内含「首次等路用户，需要完善个人信息」。意思更接近字幕，但缺少该句的独立时间，不能据此断言第 43 秒正在说这句 |

48 秒是根据语音活动追加的口播核查点，不计入五个画面问题。该教程说明，相邻采样帧、覆盖查询时刻的识别区间、原片同期字幕，三者可能指向不同内容。

## 运行条件与复测入口

- **AgentMediaLens** 使用已配置且有可用访客身份的 Evil0ctal 读取服务。主测指定 `discardOriginal: true`，使用默认采样间隔 4 秒、最多 30 帧和本机实际选中的 `base` 模型。用 `media_analyze` 提交链接，完成后分别调用 `media_get_frame(timestamp)`、`media_get_transcript(start, end)`。图片工具同时返回 JPEG、帧 ID 和实际采样时间。另用默认留存设置重跑 B 站样本，结果依然标记 `public_playback`、`retained: false`。[MCP 工具](../../apps/mcp-server/main.ts) · [读取服务配置](../providers/bilibili.md)
- **bilibili-douyin-notes** 固定到 `59fadaa`，使用游客流程与本地 `small` 模型。先运行对应平台的 fetch 脚本，B 站未取到平台字幕，再运行 `bili_transcribe.py`。对每个时刻先用 `bili_screenshot.py --shots`，再给转写区间加 `--candidates` 并查看网格和候选时间。该版本对指定时间尝试向后选更适合作插图的帧，且校验转写锚点。补测用它取得的本地抖音媒体和它的 B 站视频读取函数，再执行 `ffmpeg -ss <秒> -i <媒体> -frames:v 1 <图片>`。[所测版本](https://github.com/lucky-Luor/bilibili-douyin-notes/tree/59fadaae2eea040bfeb578c541e27782115cb1fb) · [截图实现](https://github.com/lucky-Luor/bilibili-douyin-notes/blob/59fadaae2eea040bfeb578c541e27782115cb1fb/scripts/bili_screenshot.py)
- **BibiGPT** 三条链接各实调一次官方字幕接口 `GET /api/v1/getSubtitle` 和一次视觉接口 `POST /api/v1/video/visuals`，六次均返回 HTTP 401 `UNAUTHORIZED`。本机缺少可用 API 凭据，没有取得字幕、截图或视觉任务 ID，按秒表现未评分。官方文档列出了 Pro 截图任务、截图链接和时间戳。[官方 API 说明](https://docs.bibigpt.co/api-reference/introduction)

## 对宣传与产品的影响

可以演示「配置好后，给 Agent 一条公开抖音或 B 站视频链接，它就能在对话里看真实画面、查带时间的口播，回答时能指出依据来自哪一秒」。B 站 03:36 是正例，00:32 是检验 Agent 能否说明证据边界的反例。以下两项是后续产品建议。

| ID / 优先级 | 问题、当前行为与证据 | 建议及预期行为 | 保持现状的风险 / 改动代价 | 状态 |
|---|---|---|---|---|
| V1 / 高 | 两条长视频分别偏后 7、8 秒，屏幕已切换。当前返回值提供实际帧时间 | 在结果中显式给出目标秒和偏差，并在可合法重新读取媒体时支持按需补一帧。以 32 秒读出 4,898、43 秒读出密码页作验收 | 容易用下一镜回答上一镜。按需读取会增加延迟，源流也可能已不可用 | 偏差已实测，功能建议 |
| A1 / 中 | 教程 43 秒落在一段 10.21 秒的转写内，但附近未检出语音。歌词出现错字时也未标低置信 | 追问时分别陈述「画面文字」和「这段识别文本」，对长段或疑似空白提示时间不确定。用 43 秒和 48 秒检查能否区分两者 | 容易把屏幕文字或邻近语句说成当秒原话。更严格的提示可能增加需复核的结果 | 已核对字幕、转写与语音活动，功能建议 |
