# 中文口播：CPU 模型和提示词对照（2026-11-10）

问题是：遇到带口音、含专名的口播，是换模型更有用，还是给当前模型一份词表？这次复用[首轮修复评估](2026-11-09_evidence-repair-review.md)中的真实样本 C，不用 ASR 自己的置信分打分。

## 样本和口径

- 从同一个 1002.7 秒的探店作品截出 5 段，共 68.7 秒。区间为左闭右开：开场 4.40–13.10、点单 125.20–145.60、调料 158.50–178.10、口感 589.30–603.95、部位讲解 818.65–824.00（单位：秒）。每段分别送入识别器，模型看不到其他段落的上下文。
- 在查看模型输出前，逐行从原画面抄录了 43 条作者字幕，共 298 个计分字符。字幕是独立参照，可能省略语气词或改写口语；以下是**与字幕的差异率**，不是独立听写测出的整条视频准确率。
- 用同一份 16 kHz 单声道 PCM 和同一生产 worker。机器为 Apple Silicon，CPU/int8，faster-whisper 1.2.1、CTranslate2 4.8.5，模型快照 base `ebe41f7`、small `536b066`。离线加载，禁止回退。耗时含每段加载模型，是单次本机用时。
- 主对照：两个模型各做空提示和同一份预定词表（潮汕、牛肉火锅、吊龙、五花趾、小鸟胃、油脂、沙茶酱）。看过四组汇总后，追加同音频风格对照，仅传「请使用简体中文和标点。」；用于区分给出专名与只要求输出格式的效果。
- 对参考和识别文本使用相同的 ICU 79.1 繁转简、NFKC 和大小写归一，仅保留字母和数字（含汉字）。逐片计算增删替字符数，除以全部参考字符总数；漏掉整段算删除。术语按“一个词在一个片段出现过”算一次；重复提到不重复计数。词表中 4 个不同词提供 6 次机会。另计输出中存在、对应字幕未出现的词表词，这不是对幻觉的诊断。
- 标点统计原始输出中的 Unicode 标点字符；另列句末符号（中英文句号、问号、叹号）。这两项是计数，**不评价断句位置是否正确**。

## 结果

| CPU 模型 | 提示 | 字符编辑数 / 298 | 与字幕的差异率 | 术语命中 | 字幕外词表词 | 标点 / 句末符号 | 用时 |
|---|---|---:|---:|---:|---:|---:|---:|
| base | 无 | 83 | 27.9% | 0/6 | 0 | 0 / 0 | 5.73 s |
| base | 领域词表 | 73 | 24.5% | 6/6 | 0 | 41 / 20 | 5.15 s |
| base | 仅格式 | 130 | 43.6% | 0/6 | 0 | 38 / 24 | 4.97 s |
| small | 无 | 58 | 19.5% | 0/6 | 0 | 0 / 0 | 16.23 s |
| small | 领域词表 | 42 | 14.1% | 5/6 | 0 | 18 / 14 | 15.92 s |
| small | 仅格式 | 45 | 15.1% | 1/6 | 0 | 6 / 5 | 15.78 s |

本样本中，base 加词表命中全部 6 次，适合在意已知专名且 CPU 预算有限时尝试。small 加词表的整体差异最小，比默认 base 少 41 次字符编辑，耗时约 2.8 倍。只要求标点时，base 虽然输出了 38 个标点，文字反而离字幕更远；small 上方向不同。可按任务选择 `--model small --strict-model --asr-prompt "已知术语"`；不据此更改插件的默认模型或给所有语言注入中文提示。

## 用自己的作品复测

先准备好 base、small 权重和合法取得的本地媒体。参考文字应先于模型输出确定；更严格的评估应当由人听写、复核，并含未用于挑选词表的其他作者和体裁。用 FFmpeg 按相应起点和时长导出各片段，例如：

```sh
ffmpeg -ss 10 -i input.mp4 -t 12 -vn -map 0:a:0 -ac 1 -ar 16000 -c:a pcm_s16le clip.wav
```

在 WAV 同目录写下自己的 `manifest.json`（此处仅演示格式）：

```json
{"vocabulary":["快门","曝光"],"stylePrompt":"请使用简体中文和标点。","clips":[{"wav":"clip.wav","reference":"先锁定曝光再按快门"}]}
```

运行 `uv run --frozen python scripts/evaluate_asr.py manifest.json --simplify`。脚本只读本地 WAV，离线调用生产 worker，输出汇总 JSON，不打印原文或转写。缺少指定模型会停止，不会把 base 回退结果计入 small。可省略 `stylePrompt` 只运行四组。可选的 `--simplify` 需要 PATH 上已有 ICU 的 `uconv`；省略时按原字形计分，不能把两种口径的数字直接相比。仓库不分发原视频、音频、逐句参考或模型权重。

## 整片复测：短片词表效果不能外推到连续解码

同一个 1002.705 秒作品，CPU/int8 base，不切音频。沿用上面的 5 个时间区间和 298 个参考字符；词表与第三轮测试一致（8 个词，用半角逗号连接，较上面的 7 词多「蘸料」）。同一词在同一区间只计一次，共 6 次命中机会。先转写整条音频，再按片段中点落入的区间对照字幕。这个指标同时受文字和时间对齐影响；它衡量 Agent 在对应时间能读到什么，不代表整片逐字正确率。五个区间都不是未见作者的盲测集。

| 整片解码方式 | 核对区间术语命中 | 字符编辑数 / 298 | 整片输出段数 / 时长中位数 |
|---|---:|---:|---:|
| 默认，无提示 | 0/6 | 92 | 474 / 1.0 s |
| 仅初始提示，8 个词 | 0/6 | 103 | 219 / 2.0 s |
| 每窗口词表，沿用模型片段（实验） | 4/6 | 167 | 69 / 8.4 s |
| 每窗口词表，同时关闭历史上下文（追加实验） | 5/6 | 245 | 47 / 13.1 s |
| 每窗口词表、逐词对齐后分短句（实验 / 生产 worker 再跑） | 5/6、4/6 | 94、106 | 199 / 3.3 s、187 / 4.0 s |

生产 worker 实测在点单段命中两词，在调酱段和约 820 秒的部位讲解各命中一词，未命中开场与约 590 秒的两次机会。所有配置在这五个区间的字幕外词表词计数均为 0；区间外没有标注。初始提示没有固定的 30 秒失效点；滚动上下文、解码分段和词表格式都会影响结果。同样的设置重跑也可能产生不同分段。逐词对齐减少了过长引用，但本样本不支持“所有文字更准”或“CPU 一律换 small”。因此保留原默认值，把此模式作为选项。

使用 `media-lens analyze "$SHARE_URL" --model base --strict-model --asr-hotwords "已知术语一,已知术语二"`；长作品需在本机配置中相应提高 `maxSeconds`，并先准备好 base。保留默认词表为空，以免提示污染证据。与不开词表、或用同样字符串传给 `--asr-prompt` 的结果比较。将先行确定的参考保存在本机，例如：

```json
{"vocabulary":["曝光"],"windows":[{"start":10,"end":14,"reference":"先锁定曝光再按快门"}]}
```

对每个完整任务运行 `uv run --frozen python scripts/evaluate_asr.py windows.json --score-transcript /path/to/task/transcript.json --simplify`。该命令按时间评分，不会把切过的短音频重新提交给模型。临时原片、逐字转写和逐句参考不入库。
