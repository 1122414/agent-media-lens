# Report the scope of creator feeds

A video detail, the owner's uploads and their collection directory are independently served resources. On Evil0ctal 5.1.11, Bilibili returned a first uploads page but refused the next page. The same owner's three public seasons yielded 23 distinct author-matched posts. The list rows omitted likes; public video details supplied all 23. A random draw from this catalog describes the collections. Coverage of every upload is unknown.

On Douyin an author with a readable public video had a rejected uploads feed and zero public collections. After a subsequent refusal the local guest capacity was exhausted. Treat a refused feed as unavailable even if its companion directory is empty. A successful detail response or an empty collection cannot verify upload access. The upstream also documents guest pagination limits for Douyin uploads.

On the Jiuzhaigou author, the uploads request reached the platform: HTTP 200 with an empty body was classified as `UPSTREAM_RISK_CONTROL` (`body.empty`). The independently requested profile card was refused after the guest cooled down. Neither result is a successful zero-item page. A separate outcome is a *successful*, possibly empty guest preview: v5.1.11 sets `meta.guest_fallback` on an immediate response and `data.result_meta.guest_fallback` on a completed polled task. Without this marker the API can appear to yield a complete or pageable list. Both successful shapes were verified with synthetic responses, not obtained live for this author. See the [upstream guest feed limits](https://github.com/Evil0ctal/Douyin_TikTok_Download_API/blob/d44264e96cae55a6df341ed4a0b81b3e2d1fbcaf/documents/en/14-troubleshooting.md).

Use `guestLimited`, `view`, `postListError`, `collectionListError` and the two cursors to record the source and any incomplete pages. Deduplicate by platform ID and check the author of every entry. Keep missing metrics null and distinguish them from an observed zero. Verified on one Bilibili creator and observed Douyin refusal cases. [Profile adapter](../../../packages/core/profile.ts) · [regression tests](../../../tests/profile.test.ts).

On the same Jiuzhaigou author, an explicitly reserved local login returned two pages via the native signer. The upstream fixture has `raw.author.secret=0`; real list rows omitted it, despite having explicit public post status and correct owner. Treating the omission as private silently discarded every row. Treating it as public would trust account-dependent data. Check the exact post as a guest and verify IDs and public status before emitting it. A nonempty cursor alone proves no works were emitted. In the live two-page check, all six unique works were independently visible; one had empty title, description, preview title and caption, while another had exactly zero likes. Preserve both facts. See [login regression tests](../../../tests/local-login.test.ts). Verified once live for this author.

A creator comparison reproduced the directory boundary: the uploads feed was refused, while the first six distinct works in an authored Bilibili collection returned like counts. The selected same-format pair was published two days apart and both videos were processed. Their sampled on-screen text was readable even though neither transcript had any segments. Preserve the collection ID, eligible count and stats times in the comparison; read both sets of frames instead of inferring differences from titles, empty ASR or likes. Verified once live; duplicates, unknown counts, ties and interrupted pagination are exercised in [selection tests](../../../tests/comparison.test.ts).
