# Compare the path from a share link to a video file

On 2026-11-18 the maintainer clarified that the main use case is retrieving the video behind a media-platform link. An earlier comparison centered on the reports a user could generate after retrieval. For this use case, compare the supported share formats, what the caller receives (metadata, a playable URL, or a saved file), and where a saved file can be opened. The [result contract](../../architecture/data-contracts.md) documents the difference between platform downloads and retained guest playback.

Include acquisition services already used by the plugin when they offer their own user-facing download path. AgentMediaLens uses Evil0ctal to resolve [Douyin](../../providers/douyin.md) and [Bilibili](../../providers/bilibili.md), then transfers the media into its own task directory. Evil0ctal also documents connecting Codex CLI directly and calling `download_media` to store media on the service instance. This overlap was verified against the [upstream MCP guide](https://github.com/Evil0ctal/Douyin_TikTok_Download_API/blob/main/documents/en/12-mcp.md). Comparative download success rates would require running the same links with comparable access.
