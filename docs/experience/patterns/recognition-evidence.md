# Recognizer failure and confidence are not observations about the source

**Signals.** A job stopped during transcription before producing frames, an artistic number was wrong despite a high OCR score, and a quiet ending disappeared when the frame budget was reduced. These are different failure mechanisms; diagnose acquisition, recognition and sampling separately.

- Model availability: test with a temporary empty Hugging Face cache and offline mode; never delete the operator’s weights. Verify a real MCP JPEG and an explicit unavailable transcript. A second test with only base cached distinguishes fallback from no model. Use the actual model and status when interpreting a result. Retain the [decoded PCM path](asr-pcm.md); a download failure and a decode failure need different remedies.
- Evidence quality: compare a candidate with the same frame, not just a confidence threshold. One 83.8-confidence reading changed a 5 into an 8. A long voiced sample returned 484 segments and zero confidence flags despite reported name errors. Neither signal measures word accuracy. Unfiltered observations and frame IDs allow independent checks.
- Sampling: measure timestamp gaps on the complete timeline. Spreading selections across change candidates can still cluster them in the introduction. On the same long work, time anchors reduced the maximum gap from 72 to 46 seconds at 30 frames. A separate 12-frame run regained a missing closing card. These are sampled seconds, not full coverage of every cut.

Model isolation and page-local OCR are regression-tested in [Python](../../../tests/test_worker.py); the [MCP integration](../../../tests/mcp.test.ts) verifies partial results cross the serialization boundary. Empirical recognition limits are verified on these samples only; see the [repair assessment](../../development/2026-11-09_evidence-repair-review.md).

Follow-up at `7977f4a`: on the same portrait performance, the visible account watermark moved from top left at 0s to bottom right at 26s. Of 30 frames, 27 retained OCR text and just two matched earlier full-frame strings; 25 distinct strings still contained 52 lines. Fixed-corner cropping would miss the moving mark and could remove subtitles. Re-running Tesseract on the archived JPEGs reproduced short candidates at widely different word scores: “GA” 60.3, “fl” 66.9, and an isolated “7” 90.1. A cutoff of 85 alone cannot identify overlays. Check actual pixels and word boxes over time before suppressing a line; preserve raw evidence. These positions and counts are verified for this sample, not a platform-wide layout rule.

Using the same archived frames after introducing line-level folding: the performance's default non-repeated OCR fell from 52 lines to 8 (22 overlay and 24 short lines folded before deduplication). All 30 raw readings were unchanged. The design clip's closing frame still contained CHROMA 02 and 1538 °C; the long clip retained its raw readings as well. Residual artifacts are expected, especially fragments of three or more letters. [Boundary fixtures](../../../tests/test_ocr_summary.py) cover moving markers, ordinary numbers next to a marker, album page isolation, short scores and abbreviations. These checks measure filtering, not recognition accuracy.

A follow-up using 30 archived performance frames showed that a centered account number on the platform end card escaped corner-only matching. The number occupied its own line; it was not a like count or embedded in the promotion sentence. Folding explicit account labels and exact, previously observed watermark digits only on a detected end card changed the default text on frames 28 and 29 alone. All 30 raw readings remained identical, and the closing slogan stayed visible. See [the end-card boundary test](../../../tests/test_ocr_summary.py).

For ASR comparisons, check the actual model and fix reference text before running any variant. In [one captioned Mandarin sample](../../development/2026-11-10_mandarin-asr-comparison.md), switching CPU models reduced character edits but did not recover any of six term opportunities without a vocabulary. A format-only prompt produced punctuation on both models yet increased character edits on base. Count term hits and character errors separately; punctuation count is not punctuation accuracy. This was verified on one work, not across creators or languages.

A missing CPU model in strict mode attempted a remote download; a cache PermissionError then stopped the job before frames. The model lookup boundary now distinguishes an inaccessible cache from missing weights. Strict mode checks only the named local snapshot; task-directory failures outside model lookup remain errors. Verified with [cache call tracing and real voiced-input frame extraction](../../../tests/test_worker.py).

A new decode for every short clip reseeds the initial prompt, unlike contiguous decoding of the same 1003-second audio. Supplying terms per window helped later names, but using long unaligned segments or dropping previous context also made time-based citations worse. Opt-in word alignment and short phrases recovered some precision; two runs matched 4–5 of 6 term opportunities, against 0 with only an initial hint. This is one source, not a general accuracy gain. [Full-recording methodology and reproduction](../../development/2026-11-10_mandarin-asr-comparison.md).

When a Markdown report and transcript display disagree, compare the same segment timestamps and offsets, not first-page totals against a full report. On one archived Mandarin task the first 100 of 180 segments showed 189 full-width commas. Before the export fix, all 411 commas in the Markdown Speech section were ASCII. Replaying the worker evidence through the writer in an isolated cache matched all 180 time labels and displayed lines (391 full-width commas, 20 ASCII), with identical raw transcript data. No ASR rerun or overwrite of the historical report was necessary. See [the export regression](../../../tests/service.test.ts) and [the transcript contract](../../architecture/data-contracts.md).
