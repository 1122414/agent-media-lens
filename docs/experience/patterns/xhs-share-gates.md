# A Xiaohongshu share can identify the note before denying its contents

Signals: a .cn or .com share may return a valid note path with parameters. The next hop can still point to /login or /404/sec_…; some older short links went to the homepage instead. One user-provided share showed the login pattern; two independent note targets showed an official error page. These observations do not identify why a note is unavailable to another viewer.

Use the original share transiently for the request; keep a query-free canonical URL only for citations. Identify tests recognition, not visibility. Stop at gates, and distinguish a metadata-only response from completed decoding. Do not change identities to turn a refusal into success. Check only sanitized paths, failure codes and whether actual frames exist.

Verified on live guest refusals. The positive input shapes and normal decoding path have offline coverage; their availability on the live platform is still unverified. See [adapter scope](../../providers/xiaohongshu.md) and [tests](../../../tests/xiaohongshu.test.ts).
