# Contributing

Start with the development setup in README.md and [verification commands](docs/development/testing.md). Keep provider-specific payloads out of Core. Preserve evidence timestamps and frame references. Add a regression check for a changed boundary and document any schema change.

Use focused conventional commits. Explain the observed trigger, behavior after the change and checks run in your pull request. Only include rights-cleared synthetic fixtures. Submit security reports privately as described in SECURITY.md.
